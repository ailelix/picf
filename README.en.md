> picf is a single-user image host on Cloudflare Workers

Built with Svelte, with files stored in R2 and data in D1


## Features

- **Format conversion**: On upload, images in the specified formats are automatically converted to a single target format (WebP, AVIF, JPEG or PNG), with configurable compression quality  
Converted images always have EXIF stripped; formats that are not converted are stored as is, with their original metadata
- **Image management**: After logging in, you can browse uploaded files, copy links or delete files
- **Anonymous uploads**: Can be enabled with an environment variable; once enabled, visitors who are not logged in can upload files on the home page, but cannot view the file list or delete files

### Image processing

picf processes images in two ways, chosen in the following order:

1. Cloudflare Images converts the image on the server first
2. When Cloudflare Images cannot process an image, the browser converts it locally with WASM (wasm-vips) and then uploads it
3. If neither method can process an image, the file is stored as is

`The Cloudflare Images free plan includes 5,000 transformations per month`

## Deployment

### One-click deployment
[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/ailelix/picf)

The process is as follows:

1. Log in to the Cloudflare dashboard and authorize access to GitHub
2. On the configuration page, enter the admin username `ADMIN_USER` and password `ADMIN_PASSWORD`
3. After you confirm, Cloudflare automatically creates the R2 bucket and D1 database and deploys picf

After deployment, you also need to configure public access for R2 as described in the next section before the site can be used  
`Until then, visiting the site shows a setup notice`

> If the dashboard says that the Images service is not enabled, enable it manually on the "Images" page

### Manual deployment

In the Cloudflare dashboard, go to "Workers & Pages" and choose "Create → Import a repository"  
Fill in the build settings as shown below

| Setting | Value |
|---|---|
| Build command | `npm run build` |
| Deploy command | `npm run deploy` |

`The R2 bucket and D1 database are also created automatically on the first deployment`

After deployment, add `ADMIN_USER` and `ADMIN_PASSWORD` under the Worker's "Settings → Variables and Secrets", then configure R2 public access as described in the next section

### Custom R2 and D1 names

The names of the R2 bucket and D1 database are set in `wrangler.jsonc`, and default to `picf-images` and `picf-db` respectively:

```jsonc
"r2_buckets": [{ "binding": "BUCKET", "bucket_name": "picf-images" }],
"d1_databases": [{ "binding": "DB", "database_name": "picf-db", "migrations_dir": "migrations" }]
```

- With one-click deployment, you can change the names directly on the configuration page, and Cloudflare writes the changes to `wrangler.jsonc` in the newly created repository
- With manual deployment, change `bucket_name` and `database_name` in your own repository, then push

> During deployment, if the account already has a bucket or database with the same name, it is bound directly instead of being created again  
> This can therefore also be used to bind an existing bucket and database  
> Database migrations run automatically during deployment for a newly bound database

Note the following:

- Do not change these two bindings on the "Bindings" page in the dashboard:  
`wrangler.jsonc` is the source of truth for bindings, and changes made in the dashboard are overwritten on the next deployment
- After switching to another bucket or database, existing files and image records are not migrated automatically
- After switching to another bucket, change `R2_PUBLIC_URL` to the public URL of the new bucket

### Configure R2 public access

Uploaded files are served directly from the public domain of the R2 bucket, without going through the Worker  
Therefore, after deployment you need to enable public access for the bucket and set its URL in the `R2_PUBLIC_URL` environment variable

1. Open "Settings" for the R2 bucket (named `picf-images` by default) and connect a domain under "Custom Domains", for example `img.example.com`  
   You can also enable the "Public Development URL" to use an `r2.dev` domain assigned by Cloudflare
2. On the same page, add the following rule under "CORS Policy":
   ```json
   [
     {
       "AllowedOrigins": ["*"],
       "AllowedMethods": ["GET", "HEAD"],
       "MaxAgeSeconds": 86400
     }
   ]
   ```
   picf pages are cross-origin isolated, so if R2 does not return CORS headers, these images cannot be viewed on the management page

3. Under the Worker's "Settings → Variables and Secrets", add the environment variable `R2_PUBLIC_URL` with the type "Text", and set it to the URL from step 1, for example `https://img.example.com`

When this is done, refresh the site and log in with the admin account to start using picf
To adjust the conversion rules, enable anonymous uploads or disable video uploads, see "Environment variables"

### Optional: configure rate limiting

`picf itself does not limit request rates`

It is recommended to configure rate limiting rules for `/login` and `POST /api/images` under "Security → WAF → Rate limiting rules" in the dashboard

## Environment variables

`All picf configuration is set through environment variables`

`ADMIN_USER` and `ADMIN_PASSWORD` are entered during one-click deployment; other variables are added or changed under the Worker's "Settings → Variables and Secrets"  
`Changes take effect as soon as they are saved, without redeploying`

### Required

| Name | Type | Description |
|---|---|---|
| `ADMIN_USER` | Secret | Admin username |
| `ADMIN_PASSWORD` | Secret | Admin password; changing it invalidates all logged-in sessions |
| `R2_PUBLIC_URL` | Text | Public URL of the R2 bucket, for example `https://img.example.com`; file links point to this URL |

### Optional

| Name | Default | Description |
|---|---|---|
| `CF_IMAGE` | `true` | Whether to prefer Cloudflare Images for image processing; when set to `false`, images are processed by the browser |
| `CONVERT_FORMATS` | `jpeg,png,bmp,tiff,heic` | Formats to convert on upload, separated by commas; accepted values are `png`, `jpeg`, `webp`, `avif`, `gif`, `tiff`, `bmp`, `ico`, `heic` and `svg`, and `jpg`, `tif` and `heif` are also accepted; set to `none` to convert no formats; `formats that are not listed are stored as is`|
| `CONVERT_TO` | `webp` | Target format for conversion; accepted values are `webp`, `avif`, `jpeg` and `png` |
| `QUALITY` | `80` | Compression quality, an integer from 1 to 100; applies to WebP, AVIF and JPEG |
| `ALLOW_ANONYMOUS` | `false` | Whether to allow anonymous uploads; when enabled, visitors who are not logged in can upload files on the home page, but cannot view the file list or delete files |
| `ALLOW_VIDEO` | `true` | Whether to allow video uploads (MP4, WebM, MOV) |
| `TIMEZONE` | `UTC` | Files are stored in R2 in "year/month/day" directories; this sets the time zone used to compute the date, as an IANA time zone name, for example `Asia/Shanghai` |

## Local development

Local development does not require a connection to Cloudflare; R2 and D1 are simulated locally by wrangler

```sh
npm install
cp .env.example .env
npx wrangler d1 migrations apply picf-db --local
npm run dev
```

`.env` sets the environment variables for local development, including the admin username and password, and the optional `CF_IMAGE`

The local R2 is simulated by wrangler and has no public domain, so `R2_PUBLIC_URL` is not needed for local development; files are served by the local `/i/` route  
`This route is only available in development mode`

Locally simulated data is stored in the `.wrangler/state` directory  
`Delete this directory to clear the data, then run the migration command again`
```sh
npx wrangler d1 migrations apply picf-db --local
```

The local Cloudflare Images is a simplified simulation that only supports resizing and format conversion

The types of the Worker's bindings and environment variables are maintained by hand in `src/app.d.ts`  
When you change the bindings in `wrangler.jsonc` or add environment variables, update this file as well

## Known limitations

- **Cross-origin isolation**: WASM processing in the browser relies on SharedArrayBuffer, which browsers only allow on cross-origin isolated pages
- **HEIC**: HEIC is not processed in the browser, so HEIC files can only be converted by Cloudflare Images; if Cloudflare Images cannot process them or is disabled, the files are stored as is
- **Video size**: Because of the Workers request body limit (100MB) and memory limit (128MB), videos are limited to 90MB
